# Versioning Policy

CLAYおよび関連モジュールのバージョン番号は、更新・作成時期や開発段階を把握するための目安として扱います。基本的には、同じパッケージ・同じ系列の中では、番号が大きいものほど新しい版であることを意図します。

ただし、すべての関連モジュールや派生プロジェクトに共通する厳密な番号体系を保証するものではありません。異なるプロジェクトのバージョン番号を直接比較しないでください。

## 利用時の考え方

- まず、利用する対象パッケージのREADMEやリリース情報で、現在の基準バージョンを確認してください。
- 新しい版を利用できる場合は、原則として新しい版を基準にしてください。
- 必要な版を持っていない場合は、手元の版と仕様を確認し、自分の環境に合わせて調整してください。
- バージョン番号が大きいことだけで、完全な互換性、後方互換性、性能向上、安全性、検証済みを意味するわけではありません。
- 互換性が必要な場合は、対応するCLAYバージョン、モジュールバージョン、依存関係、変更点、検証結果を個別に確認してください。

## 派生版・改変版で推奨する記録

独自に変更した場合は、少なくとも次を記録することを推奨します。

- 元になったCLAY・モジュールの名前とバージョン。
- 改変した日付またはリビジョン。
- 変更内容と変更理由。
- 動作確認に使ったLLM・端末・環境。
- 実施したテストと未検証範囲。

独自のバージョン番号を付ける場合は、公式版と誤認されないようにしてください。再配布条件は現行の `LICENSE` に従い、将来の方針案と混同しないでください。
