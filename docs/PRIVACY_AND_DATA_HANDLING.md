# Privacy and Data Handling

**個人情報と機密情報の保護は、CLAYを利用・検証・共有する際の重要な原則です。**

この文書は利用上の注意と開発方針を示すもので、CLAY本体にローカル専用ストレージ、完全な匿名化、送信防止機能が実装済みだと保証するものではありません。

## 1. 基本方針

- 個人を特定できる情報は、必要性がない限り入力しない。
- 患者情報、顧客情報、従業員情報、家族・知人の情報、アカウント識別情報など、第三者を含む情報を不用意にLLMへ渡さない。
- 必要な情報だけを最小限にする。
- 個人情報や機密情報は、可能な範囲で利用者が管理するローカル環境に保持し、外部へ送る前に必要性と内容を確認する。
- 公開Issue、コミュニティ投稿、テストレポート、スクリーンショット、ログには、個人情報や秘密情報を含めない。
- APIキー、パスワード、パスキーの秘密情報、アクセストークン、秘密鍵をプロンプトや公開資料に記載しない。

## 2. LLMへの入力前の確認

外部LLMへ送信する前に、次を確認してください。

1. この情報をLLMに渡す必要が本当にあるか。
2. 個人名、住所、電話番号、メール、患者番号、顧客番号、位置情報などを削除・置換できないか。
3. 固有の組み合わせによって個人が特定されないか。
4. 第三者の同意や組織上の権限が必要ではないか。
5. 利用するプラットフォームのデータ処理・保存・学習に関する条件を理解しているか。
6. LLMへの送信が許されない情報ではないか。

## 3. LLMによる複数回チェックの限界

LLMに複数回確認させることは、漏洩しそうな情報を見つける補助にはなります。しかし、LLM自身が見落とす可能性があるため、複数回の確認だけで安全が保証されるわけではありません。

より重要なのは、送信前にローカル側で不要な情報を除去し、匿名化・マスキングし、人間が最終確認することです。固有の文脈や複数項目の組み合わせから本人を推測できる場合もあるため、単純な名前置換だけでは不十分なことがあります。

## 4. ローカル保存とアカウント認証は別の問題

ローカルで情報を保持することは、外部送信を抑えるうえで役立つ場合があります。ただし、CLAY v0.4.3の資料上、CLAY自体が完全なローカル個人情報データベースや永続保存機能を提供するわけではありません。実際の保存場所、暗号化、バックアップ、アクセス制御は利用者が使うホストやアプリケーションに依存します。

パスキーや多要素認証はアカウントへの不正アクセスを防ぐための認証手段です。LLMに送った会話内容やファイルの情報開示を直接防ぐ仕組みではありません。認証対策とデータ送信前の情報管理を混同しないでください。

## 5. フィードバック・公開テスト時

- 実際の患者・顧客・家族・知人の記録をそのまま使わない。
- 合成データ、架空の例、十分に匿名化した最小データを使用する。
- スクリーンショットやログの端、通知、アカウント名、ファイル名にも個人情報が写り込んでいないか確認する。
- 公開前に人間が確認する。
- 誤って情報を公開した場合は、可能な限り速やかに公開範囲を制限し、プラットフォームや組織の手順に従って対応する。

## 6. 目指す方向

CLAYでは、利用者がどの情報を保存し、どの情報をLLMに渡し、どの情報を外部へ共有するかを理解・管理しやすくする方向を重視します。ローカル管理、送信前の検査、必要最小限の共有、明示的な確認などは今後の設計・検証対象です。現行版で実装済みかどうかは、コードとホスト環境を個別に確認してください。
